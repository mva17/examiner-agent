# КП2 — раздел Масляева Вячеслава: агент-Экзаменатор + API и чат

Команда 43 «Deep Learning Poor Eating» · проект «ИИ-ассистент по лабораторному практикуму физики НИЯУ МИФИ на основе архитектуры Agentic RAG».
Репозиторий модуля: https://github.com/mva17/examiner-agent

## 1. Роль и зона ответственности

**Агент-Экзаменатор** — тренажёр допуска к лабораторной работе (главная часть вклада). Дополнительно — **API на FastAPI и чат на Streamlit** для всей системы.

## 2. Что сделано

- Граф LangGraph Экзаменатора из 13 узлов: выделение темы → поиск по методичкам → проверка релевантности (фильтр + LLM) → переформулировка и повторный поиск → вопросы из методички («Контрольные вопросы», затем по тексту, со страницей) **или** генерация вопросов «не из методички» с проверкой **или** отказ → вопрос с `interrupt` (ожидание студента) → оценка «верно / частично / неверно» → уточняющий вопрос → выбор следующего вопроса с учётом ошибок → итог.
- Краткосрочная память (checkpointer, `thread_id = user_id:chat_id`) и долгая память слабых тем и вопросов с ошибками (SQLite, `user_id`): в новой сессии сначала повторяются вопросы с ошибками.
- Структурированный вывод: 7 Pydantic-схем, проверка каждого ответа модели и повтор при невалидном JSON, срезание `<think>` у Qwen3.
- Гардрейлы: лимит вопросов и вызовов модели на сессию (по исчерпании — корректный итог, а не падение), лимит попыток поиска, `recursion_limit`, запасная модель (`with_fallbacks`), ошибки модели → понятное сообщение; защита от prompt injection в двух слоях (данные в тегах + фильтр до вызова модели).
- Поиск через интерфейс `ManualSearch`: локальный BM25 по 2 ДЕМО-текстам (**не методички МИФИ**) и готовый адаптер к ChromaDB Оскара с разбором «Контрольных вопросов».
- Точка подключения Проверяющего (`QuestionVerifier`): пока работает самопроверка отдельным вызовом модели.
- FastAPI: `/chat`, `/exam/start`, `/exam/answer` (`/resume`), `/memory/{user_id}`, `/feedback`, `/upload` (проверка типа и размера фото для Расчётчика), `/health`; валидация входа, коды 409/422/503, время ответа в заголовке.
- Чат Streamlit: статус шагов агента, цветная оценка со страницей, метка «не из методички», источники, кнопки «полезно / нет» (продуктовая метрика), слабые темы в боковой панели.
- 67 автотестов на фейковой модели (без ключа): граф целиком, API, поиск, память, логика, разбор JSON, скрипты метрик.
- Бенчмарк оценки ответов на ruMMLU (MERA, физика) с baseline «LLM без эталона», скрипт статистики отзывов.

Скриншоты: `docs/img/chat_micrometer.png` (сессия по методичке: верно → верно → «не знаю» с правильным ответом и страницей), `docs/img/chat_general.png` (тема вне базы → вопросы «не из методички», прошедшие проверку), `docs/img/chat_refusal.png` (не физика → отказ). Скриншоты сделаны на демо-модели без ключа.

## 5. Ограничения

- В базе 2 ДЕМО-текста, не методички МИФИ; качество поиска на настоящих методичках зависит от базы Оскара.
- ruMMLU — тест с вариантами ответа, а на допуске отвечают свободным текстом: бенчмарк проверяет оценщика, но не весь диалог.
- Вопросы «не из методички» проверяются той же моделью, что их сгенерировала (до подключения Проверяющего).
- Незаконченная сессия теряется при перезапуске сервера (`InMemorySaver`).
- Компромисс «долго / дорого / плохо»: `temperature=0` и одна оценка на ответ (без голосования нескольких проверок) — дёшево и воспроизводимо, но без защиты от единичной ошибки оценщика.
